1 Getting Started시작하기

What is Looper?Looper란 무엇인가요?

Looper is an AI-powered coding assistant that automates development tasks using a Plan-Do-Check loop. You describe what you want built in plain language, and Looper's AI agent will plan the work, write the code, then verify it by running tests, linters, and type checks. If verification fails, it automatically tries again with fixes until everything passes. Think of it as an autonomous developer you can assign tasks to — no coding knowledge required. Looper는 Plan-Do-Check 루프를 사용하여 개발 태스크를 자동화하는 AI 기반 코딩 어시스턴트입니다. 원하는 작업을 일반 언어로 설명하면, Looper의 AI 에이전트가 작업을 계획하고, 코드를 작성한 다음, 테스트, 린터, 타입 검사를 실행하여 검증합니다. 검증에 실패하면 모든 것이 통과할 때까지 자동으로 수정을 시도합니다. 태스크를 할당할 수 있는 자율적인 개발자라고 생각하시면 됩니다 — 코딩 지식이 필요하지 않습니다.

2.2 — Connecting a Repository2.2 — 저장소 연결

Before creating tasks, you need to connect a code repository that Looper will work on.태스크를 생성하기 전에 Looper가 작업할 코드 저장소를 연결해야 합니다.

  1. Open Settings설정 열기

    Click the Settings item in the left sidebar (gear icon), then scroll to the Repositories section.왼쪽 사이드바에서 Settings 항목(톱니바퀴 아이콘)을 클릭한 다음, Repositories 섹션으로 스크롤하세요.

  2. Add a repository저장소 추가

    Choose one of two methods:두 가지 방법 중 하나를 선택하세요:

    • Option A — Local Path: Type the full path to a Git repository already on your computer (e.g. /home/user/my-project) and click Add Repository.옵션 A — 로컬 경로: 컴퓨터에 이미 있는 Git 저장소의 전체 경로를 입력하고 (예: /home/user/my-project) Add Repository를 클릭하세요.
    • Option B — GitHub: In the GitHub Integration section, connect your GitHub account, browse your repositories, then click Clone & Add on the one you want.옵션 B — GitHub: GitHub 연동 섹션에서 GitHub 계정을 연결하고, 저장소를 찾아 원하는 저장소에서 Clone & Add를 클릭하세요.
  3. Activate the repository저장소 활성화

    After adding, click Activate next to the repository name. The active repository is highlighted and will be used for all new tasks and loops.추가 후, 저장소 이름 옆의 Activate를 클릭하세요. 활성화된 저장소가 강조 표시되며 모든 새 태스크와 루프에 사용됩니다.

2.3 — Creating Tasks2.3 — 태스크 생성

There are two ways to create tasks in the dashboard:대시보드에서 태스크를 생성하는 두 가지 방법이 있습니다:

Method A: Manual Creation방법 A: 수동 생성

  1. Click "+ New Task""+ New Task" 클릭

    Click the + New Task button in the top-right corner of the Kanban board, or press the N key.칸반 보드 오른쪽 상단의 + New Task 버튼을 클릭하거나, N 키를 누르세요.

  2. Fill in the details세부 사항 입력
    • Title — A short, descriptive name (e.g. "Add user login page").제목 — 짧고 설명적인 이름 (예: "사용자 로그인 페이지 추가").
    • Description — A detailed explanation of what needs to be done. The more detail you provide, the better the AI will perform.설명 — 수행해야 할 작업에 대한 자세한 설명. 더 자세한 설명을 제공할수록 AI의 성능이 향상됩니다.
    • Priority — Choose Critical, High, Medium, or Low.우선순위 — Critical, High, Medium, Low 중 선택하세요.
  3. Submit제출

    Click Create Task. The task appears in the Backlog column of the Kanban board.Create Task를 클릭하세요. 태스크가 칸반 보드의 Backlog 열에 나타납니다.

Method B: PM Agent (AI-Powered Decomposition)방법 B: PM 에이전트 (AI 기반 분해)

The PM Agent lets you describe a large feature and have AI break it into smaller, actionable subtasks automatically.PM 에이전트를 사용하면 큰 기능을 설명하고 AI가 자동으로 더 작고 실행 가능한 하위 태스크로 분해하게 할 수 있습니다.

  1. Open the PM Agent tabPM 에이전트 탭 열기

    Click PM Agent in the sidebar navigation.사이드바 네비게이션에서 PM Agent를 클릭하세요.

  2. Describe your goal목표 설명

    Write a high-level description of the feature or change you want. For example: "Add user authentication with email and password, including login, signup, and password reset pages."원하는 기능이나 변경 사항에 대한 상위 수준의 설명을 작성하세요. 예: "이메일과 비밀번호를 사용한 사용자 인증을 추가하고, 로그인, 회원가입, 비밀번호 재설정 페이지를 포함합니다."

  3. Click "Decompose with AI""Decompose with AI" 클릭

    The PM Agent analyzes your description and generates a set of subtasks, each with its own title, description, and priority.PM 에이전트가 설명을 분석하고 각각 제목, 설명, 우선순위가 있는 하위 태스크 세트를 생성합니다.

  4. Review and create검토 및 생성

    Review the generated subtasks. You can edit or remove any you do not need. Then click Create Tasks to add them all to the Kanban board.생성된 하위 태스크를 검토하세요. 필요하지 않은 것은 수정하거나 제거할 수 있습니다. 그런 다음 Create Tasks를 클릭하여 모두 칸반 보드에 추가하세요.

Tip: The PM Agent works best when you describe the what and why, not the how. Let the AI figure out the implementation details.팁: PM 에이전트는 어떻게가 아닌 무엇을, 왜를 설명할 때 가장 잘 작동합니다. 구현 세부 사항은 AI에게 맡기세요.

2.5 — Running a Loop2.5 — 루프 실행

This is where Looper does its core work. A loop assigns an AI agent to automatically plan, code, and verify your task.여기서 Looper가 핵심 작업을 수행합니다. 루프는 AI 에이전트를 할당하여 태스크를 자동으로 계획, 코딩, 검증합니다.

  1. Select a task태스크 선택

    Click on any task card in the Kanban board to open the detail panel.칸반 보드에서 태스크 카드를 클릭하여 디테일 패널을 여세요.

  2. Click "Start Loop""Start Loop" 클릭

    Press the Start Loop button in the detail panel. The AI agent begins working immediately.디테일 패널에서 Start Loop 버튼을 누르세요. AI 에이전트가 즉시 작업을 시작합니다.

  3. Watch real-time progress실시간 진행 상황 확인

    The detail panel shows live updates as the agent works through each phase:디테일 패널에 에이전트가 각 단계를 수행하면서 실시간 업데이트가 표시됩니다:

    • Plan — The agent analyzes the task and codebase, then creates a step-by-step implementation plan.Plan — 에이전트가 태스크와 코드베이스를 분석하고 단계별 구현 계획을 작성합니다.
    • Do — The agent writes and modifies code according to the plan.Do — 에이전트가 계획에 따라 코드를 작성하고 수정합니다.
    • Check — The agent verifies the work by running tests, linters, type checkers, and the build process.Check — 에이전트가 테스트, 린터, 타입 체커, 빌드 프로세스를 실행하여 작업을 검증합니다.
  4. Review the result결과 확인

    When the loop finishes:루프가 완료되면:

    • PASS — All checks succeeded. The task automatically moves to the Done column.PASS — 모든 검사를 통과했습니다. 태스크가 자동으로 Done 열로 이동합니다.
    • FAIL (after maximum retries) — The task moves to the Review column for your attention.FAIL (최대 재시도 후) — 태스크가 주의가 필요한 Review 열로 이동합니다.

Good to know: Each loop iteration is recorded as a Git commit with special metadata (Loop-Phase, Loop-Iteration, Loop-Verdict). You can always review the AI's changes through Git history.알아두세요: 각 루프 반복은 특별한 메타데이터(Loop-Phase, Loop-Iteration, Loop-Verdict)와 함께 Git 커밋으로 기록됩니다. Git 히스토리를 통해 언제든지 AI의 변경 사항을 검토할 수 있습니다.

3 CLI Guide (Without Dashboard)CLI 가이드 (대시보드 없이)

If you prefer working in the terminal, or do not need the visual dashboard, you can use Looper directly from the command line.터미널에서 작업하는 것을 선호하거나 시각적 대시보드가 필요하지 않은 경우, 커맨드라인에서 직접 Looper를 사용할 수 있습니다.

3.1 — Install the Plugin3.1 — 플러그인 설치

Terminal 
claude plugin install vikyw89/looper

This installs Looper as a plugin for the Claude CLI. You only need to run this once.이렇게 하면 Looper가 Claude CLI의 플러그인으로 설치됩니다. 한 번만 실행하면 됩니다.

3.2 — Run a Loop3.2 — 루프 실행

Navigate to your project directory, start the Claude CLI, then invoke the loop skill:프로젝트 디렉토리로 이동하고, Claude CLI를 시작한 다음, 루프 스킬을 호출하세요:

Terminal 
cd /path/to/your/project
claude
> /loop "Add user authentication with JWT"

Replace the text in quotes with a description of your task. Be specific and detailed for best results.따옴표 안의 텍스트를 태스크 설명으로 바꾸세요. 최상의 결과를 위해 구체적이고 자세하게 작성하세요.

Tip: Write clear, specific task descriptions. Instead of "fix the bug", try "Fix the login form validation error that occurs when the email field is left empty."팁: 명확하고 구체적인 태스크 설명을 작성하세요. "버그 수정" 대신 "이메일 필드를 비워두었을 때 발생하는 로그인 폼 유효성 검사 오류를 수정하세요."와 같이 작성하세요.

3.3 — Understanding Output3.3 — 출력 이해하기

When you run a loop, the CLI displays progress through each phase:루프를 실행하면 CLI에 각 단계의 진행 상황이 표시됩니다:

  1. Plan PhasePlan 단계

    The Planner agent analyzes your task description and the current codebase, then creates a detailed implementation plan.Planner 에이전트가 태스크 설명과 현재 코드베이스를 분석한 다음, 상세한 구현 계획을 작성합니다.

  2. Do PhaseDo 단계

    The Doer agent writes code, creates or modifies files, and commits changes according to the plan.Doer 에이전트가 계획에 따라 코드를 작성하고, 파일을 생성 또는 수정하고, 변경 사항을 커밋합니다.

  3. Check PhaseCheck 단계

    The Checker agent verifies the work by running your project's test suite, linter, type checker, and build process.Checker 에이전트가 프로젝트의 테스트 스위트, 린터, 타입 체커, 빌드 프로세스를 실행하여 작업을 검증합니다.

    • If checks PASS — the task is complete and all changes are committed to Git.검사를 PASS하면 — 태스크가 완료되고 모든 변경 사항이 Git에 커밋됩니다.
    • If checks FAIL — the loop returns to the Plan phase with error details and tries again automatically.검사를 FAIL하면 — 루프가 오류 세부 정보와 함께 Plan 단계로 돌아가 자동으로 다시 시도합니다.

3.4 — Viewing History3.4 — 히스토리 보기

Every loop iteration creates Git commits with special trailers. You can filter your Git log to see only loop-related commits:모든 루프 반복은 특별한 트레일러가 포함된 Git 커밋을 생성합니다. Git 로그를 필터링하여 루프 관련 커밋만 볼 수 있습니다:

Terminal 
git log --grep="Loop-Phase:"

Each commit message includes these metadata trailers:각 커밋 메시지에는 다음 메타데이터 트레일러가 포함됩니다:

  • Loop-Phase: plan|do|check — Which phase produced this commit.Loop-Phase: plan|do|check — 이 커밋을 생성한 단계.
  • Loop-Iteration: 1 — The iteration number (starts at 1).Loop-Iteration: 1 — 반복 번호 (1부터 시작).
  • Loop-Verdict: PASS|FAIL — The check result (only present on Check-phase commits).Loop-Verdict: PASS|FAIL — 검사 결과 (Check 단계 커밋에만 존재).

Tip: The dashboard reads these same Git commits to display Loop History. You can switch between CLI and dashboard workflows seamlessly.팁: 대시보드는 이와 동일한 Git 커밋을 읽어 루프 히스토리를 표시합니다. CLI와 대시보드 워크플로우를 원활하게 전환할 수 있습니다.

5 Troubleshooting문제 해결

PM Agent not workingPM 에이전트가 작동하지 않음

Make sure the Claude CLI is installed and accessible in your PATH. Verify by running which claude in the terminal. If you are using an API key, check that it is correctly set as an environment variable (ANTHROPIC_API_KEY).Claude CLI가 설치되어 있고 PATH에서 접근 가능한지 확인하세요. 터미널에서 which claude를 실행하여 확인하세요. API 키를 사용하는 경우, 환경 변수(ANTHROPIC_API_KEY)로 올바르게 설정되어 있는지 확인하세요.

Loop not starting루프가 시작되지 않음

Ensure a repository is configured and activated in Settings > Repositories. The repository must be a valid Git repository. The loop needs an active repository to know where to work.Settings > Repositories에서 저장소가 구성되고 활성화되어 있는지 확인하세요. 저장소는 유효한 Git 저장소여야 합니다. 루프는 작업할 위치를 알기 위해 활성 저장소가 필요합니다.

Dashboard not loading대시보드가 로드되지 않음

Verify that Node.js (v18 or later) is installed by running node --version. Then run npm install in the dashboard directory to reinstall dependencies. Finally, run npm start and check for error messages in the terminal output.node --version을 실행하여 Node.js(v18 이상)가 설치되어 있는지 확인하세요. 그런 다음 dashboard 디렉토리에서 npm install을 실행하여 의존성을 재설치하세요. 마지막으로 npm start를 실행하고 터미널 출력에서 오류 메시지를 확인하세요.

Loop keeps failing루프가 계속 실패함

Check the Loop History view for detailed error messages. Common causes include: missing project dependencies (run your project's install command first), pre-existing test failures in the codebase, or overly broad task descriptions. Try breaking large tasks into smaller, focused ones using the PM Agent.Loop History 뷰에서 상세한 오류 메시지를 확인하세요. 일반적인 원인: 프로젝트 의존성 누락(먼저 프로젝트의 install 명령 실행), 코드베이스의 기존 테스트 실패, 또는 지나치게 광범위한 태스크 설명. PM 에이전트를 사용하여 큰 태스크를 더 작고 집중된 태스크로 나눠 보세요.

6 Glossary용어 설명

Loop
An automated Plan-Do-Check cycle where an AI agent plans the work, writes the code, and verifies the result. If verification fails, it loops again.AI 에이전트가 작업을 계획하고, 코드를 작성하고, 결과를 검증하는 자동화된 Plan-Do-Check 사이클. 검증에 실패하면 다시 루프합니다.
PDC (Plan-Do-Check)
The core methodology Looper uses. Each iteration goes through three phases: planning the approach, doing the coding, and checking the results.Looper가 사용하는 핵심 방법론. 각 반복은 접근 방식 계획, 코딩 실행, 결과 검증의 세 단계를 거칩니다.
Iteration
One complete cycle through Plan, Do, and Check. If the Check phase fails, a new iteration begins. Iteration numbers start at 1.Plan, Do, Check를 거치는 하나의 완전한 사이클. Check 단계가 실패하면 새로운 반복이 시작됩니다. 반복 번호는 1부터 시작합니다.
Verdict
The result of the Check phase — either PASS (all tests, lint, and type checks succeeded) or FAIL (one or more checks did not pass).Check 단계의 결과 — PASS (모든 테스트, 린트, 타입 검사 성공) 또는 FAIL (하나 이상의 검사 미통과).
PM Agent
An AI-powered project management assistant that takes a high-level feature description and automatically decomposes it into smaller, actionable subtasks suitable for individual loops.상위 수준의 기능 설명을 받아 개별 루프에 적합한 더 작고 실행 가능한 하위 태스크로 자동 분해하는 AI 기반 프로젝트 관리 어시스턴트.
Kanban Board
A visual task management board with columns representing workflow stages: Backlog, Planning, In Progress, Review, and Done.워크플로우 단계를 나타내는 열이 있는 시각적 태스크 관리 보드: Backlog, Planning, In Progress, Review, Done.
Worktree
A separate Git working directory that Looper creates for each loop session, allowing the AI agent to work without interfering with your main branch.Looper가 각 루프 세션에 대해 생성하는 별도의 Git 작업 디렉토리로, AI 에이전트가 메인 브랜치를 방해하지 않고 작업할 수 있게 합니다.
